Technical Impression
The implementation of this project required careful consideration of distributed system design and concurrency control. The most challenging aspect was implementing Two-Phase Commit (2PC), ensuring that all replicas first prepare for a commit before actually writing data. This required designing remote methods (preparePut, commitPut, prepareDelete, commitDelete), ensuring that all replicas either commit or abort an operation together. If any replica fails the prepare phase, the entire transaction is aborted to maintain strong consistency. This approach prevents data divergence but introduces latency due to network round-trips.

Another key challenge was handling remote communication errors. Since servers must connect to multiple replicas upon startup, there was an initial issue where a server might try to connect to replicas before they were fully initialized, leading to Connection refused errors. This was resolved by handling exceptions gracefully and allowing dynamic discovery of replicas after startup. Additionally, we optimized the startup sequence by letting each server register itself first before attempting to connect to others.

Concurrency was also a significant consideration, as multiple clients may access the system simultaneously. To ensure thread safety, we used a ConcurrentHashMap for storage and applied a ReentrantReadWriteLock to synchronize read/write operations. This ensures that GET operations can be performed in parallel while PUT and DELETE operations follow mutual exclusion to prevent race conditions.

Overall, this project was a valuable exercise in distributed transactions, fault tolerance, and concurrent programming. The implementation meets the requirements effectively, but an area for improvement could be handling server failures and retries to make the system even more robust in real-world scenarios.
