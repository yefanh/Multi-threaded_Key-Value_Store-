Assignment Overview
This project extends the previous multi-threaded, RPC-based Key-Value Store system by incorporating fault-tolerant consensus through the Paxos algorithm. The goal is to ensure consistency across five replicated state machine servers, even in the presence of failures. In Project 3, Two-Phase Commit (2PC) was used to ensure consistency, but 2PC is not fault-tolerant and can stall under certain failure conditions. In contrast, Project 4 implements the roles of Paxos—Proposer, Acceptor, and Learner—across five distributed replicas using Java RMI. The system simulates intermittent failures by randomly disabling acceptors, demonstrating how Paxos achieves consensus despite partial failure. Clients can connect to any replica and issue PUT, GET, and DELETE operations. GETs are performed locally, while PUT and DELETE operations go through the Paxos protocol to reach agreement before updates are applied.
